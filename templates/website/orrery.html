Every test run, in one queryable record.

Orrery is Cthonica’s analysis backend. Astrolabe sends it every run from the bench. Orrery checks each one against rules you write, explains what changed, and keeps a record your QA, firmware, and release teams can search months later.

What happens to that run

The bench finished at 14:18 on 14 October. Here is everything Orrery did with the run, in order, with the files it read and wrote along the way.

  1. 14:18:12

    Astrolabe uploads the run

    Astrolabe asks for presigned URLs, then streams the manifest and NDJSON artifacts straight to storage. Uploads are idempotent by run_id and resume where they stopped, so a dropped bench connection never makes a duplicate.

  2. 14:18:14

    Checksums and schema are verified

    Every file is checked against its SHA-256 from the bench. The manifest is checked against the schema before anything else reads it, so a malformed run is rejected at the door instead of surfacing later as a strange chart.

  3. 14:18:16

    A rule fires

    Rules are YAML files versioned with your test plan: thresholds, regressions against a golden run, schema checks, and signal shape. Each rule is pinned to the plan version that ran it, so re-checking an old run gives the same answer it gave then. 

    # rules/thermal/temp_drift.yaml
id:        temp_drift_exceeds_2σ
kind:      regression
severity:  critical
plan:      plan-thermal-v4
match:
  channel:  "channels.ndjson:temp_c"
  where:    "phase == 'soak'"
assert:
  type:       band
  baseline:   plan.golden_run
  tolerance:  2    # σ
  duration_ms: 500
  4. 14:19:02

    Claude writes the analysis

    Claude Sonnet reads the run’s artifacts next to the golden run and writes down what changed, which rules fired, and the likely cause. Every claim points at the rows it came from, so an engineer can check it in one click.

Three endpoints carry the whole product

Astrolabe calls these so you don’t have to. The dashboard, rules engine, and reports are all built on the same three.

MethodPath or eventWhat it does
POST /api/v1/runs/upload Returns presigned URLs for the manifest and artifacts. Idempotent on run_id.
GET /api/v1/runs Queries runs by any manifest field, with cursor pagination. Uses the same filters as dashboard URLs.
Webhook run.analyzed Sent when an analysis is saved, with the verdict, rules fired, and a permalink.

Before and after a shared backend

Shared drives and tribal knowledge

  • Each engineer has their own folder layout, and the schema lives in someone’s head.
  • A failed run is a screenshot in Slack and a CSV nobody can find a week later.
  • Regressions are caught when a customer files a ticket, not when the bench produces them.
  • Release sign-off is a meeting, and the evidence is whatever was on screen at the time.

One backend, one schema, one URL per run

  • Every run arrives with its manifest, checksums, and plan version, and the schema is enforced on upload.
  • A failed run has a permalink, its artifacts, the rules that fired, and a written analysis.
  • Regressions show up when the rule fires, and the webhook tells CI before anyone opens the dashboard.
  • Release sign-off is a signed report that traces back to the exact files behind it.
