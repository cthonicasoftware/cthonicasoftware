How a run gets from the bench to a release.

Astrolabe owns the first half, Orrery the second. Nothing is handed off by email or a shared drive in between.

  1. I

    Capture

    astrolabe capture

    Reads from serial ports, TCP sockets, or files you already have (CSV, JSONL, raw logs) and stores each run locally first.

    A dropped connection doesn’t lose a run.

  2. II

    Upload

    astrolabe upload

    Sends stored runs to Orrery. Uploads resume where they stopped, retry on failure, and never arrive twice.

    Every run captured at the bench reaches the record once.

  3. III

    Analyze

    In Orrery

    Checks each run’s manifest and artifacts against your validation rules, with optional AI analysis.

    Filter by project and compare runs instead of rebuilding context from folders.

  4. IV

    Ship

    In Orrery

    Release decisions cite the exact manifest, artifacts, and rule set behind them.

    When someone asks why a build shipped, the answer is already on the record.

Two instruments, one record.

Astrolabe

Capture, at the bench

Built for unstable rigs and patchy networks. Stores a complete run locally before anything else happens.

  • Captures from serial ports, TCP sockets, or existing CSV, JSONL, and raw log files.
  • Keeps captures safe on disk while the network is down.
  • Uploads to Orrery with automatic retry, resume, and no duplicates.
Use Astrolabe free

Orrery

Analysis, for the team

Turns Astrolabe runs into a project record that engineers, QA, and release owners can question.

  • Receives run manifests and artifacts as one source of truth for test data.
  • Runs your validation rules on each test run, with optional AI analysis.
  • Shows results in a dashboard you can filter and scope by project.
